CLOUD-BASED STUDENT COMPUTER LABORATORY MONITORING AND MANAGEMENT SYSTEM
USER GUIDE (QUICK REFERENCE)
================================================================================
Version: 1.0.0 | August 2026
Stack: Node.js + Express + Socket.IO + MongoDB Atlas + React (Vite)
================================================================================

--------------------------------------------------------------------------------
1. WHAT IT DOES
--------------------------------------------------------------------------------
Monitors lab PCs and students from a cloud dashboard:
  - Live PC status (online / in-use / offline / fault) + CPU/RAM/foreground app
  - Automatic attendance tracking from student logins
  - Blocks prohibited apps and detects unauthorized USB devices
  - Remote commands: message, lock, unlock, shutdown, restart
  - Reports (utilization, violations, attendance exports) + real-time alerts

--------------------------------------------------------------------------------
2. ARCHITECTURE (3 parts)
--------------------------------------------------------------------------------
  [Lab PCs: Agent] ──► [Cloud Server: Express + Socket.IO] ──► MongoDB Atlas
                               ▲
                               └── [Web Dashboard: React app]

  - Agent (on each PC) reports telemetry every few seconds.
  - Server stores data and pushes live updates to the dashboard.
  - MongoDB Atlas is the cloud database (no local install needed).

4. HOW TO RUN (local)
--------------------------------------------------------------------------------
  Backend:  cd server  && npm install && npm run dev   → port 5000
  Frontend: cd dashboard && npm install && npm run dev → port 5173
  Browser:  http://localhost:5173
  In production: Render hosts the server, Vercel hosts the dashboard.

--------------------------------------------------------------------------------
5. PAGES QUICK GUIDE
--------------------------------------------------------------------------------
  Dashboard    6 summary cards (machines, online, active sessions,
               violations, labs, today's attendance) + live alert list
  Labs         Manage labs (add/delete, capacity, machine count)
  Machines     Status grid + control panel (see §6) per machine
  Attendance   Filter by lab/date, view check-in/out, export CSV/PDF
  Policies     Blocked apps, USB, time, idle-timeout rules (with debounce)
  Violations   open → acknowledged → resolved (acknowledge/resolve alerts)
  Reports      Sessions trend, violation trends, machine utilization charts
  Users        Admin only: add/deactivate staff accounts
  Students     Pre-register or fix student names/matric numbers

--------------------------------------------------------------------------------
6. MACHINE CONTROL PANEL (click a machine card)
--------------------------------------------------------------------------------
  Two panels:
  a) ATTENDANCE / SESSION — pick a student from dropdown → "Start Session
     (Mark Attendance)" → auto-records check-in, machine becomes "in-use".
     "End Session" records check-out and machine returns to "online".
  b) REMOTE COMMANDS — Send Message, Lock, Unlock, Shutdown, Restart.
     Status: pending → delivered → executed / failed.

--------------------------------------------------------------------------------
7. HOW ATTENDANCE WORKS (fully automatic)
--------------------------------------------------------------------------------
  Check-in  = session started      Check-out = session ended
  A session can be started 3 ways (same result):
    1. Dashboard: machine card → student dropdown → Start Session
    2. PC kiosk:  student types matric at http://<pc-address>:3001
    3. API:       POST /api/sessions/dashboard/start (admin/tech token)
                  or POST /api/sessions/start (agent token)
  Edge case: PC crashes/power loss → cron (every 5 min) closes session as
  "forcefully-terminated" and marks attendance "no-checkout".
  NOTE: a machine MUST be assigned to a lab or attendance won't be created.

  New matric number? The system auto-creates the Student record.

--------------------------------------------------------------------------------
8. REAL-TIME EVENTS (Socket.IO, no refresh)
--------------------------------------------------------------------------------
  machine:status-changed   card color changes
  session:started/ended    active session counts update
  telemetry:live           CPU/RAM % update every 15s
  alert:new / alert:updated  violations appear/update instantly
  command:status-changed   command completion

--------------------------------------------------------------------------------
9. SECURITY
--------------------------------------------------------------------------------
  - JWT auth on all routes; agents use a pre-shared registration token
  - bcrypt password hashing, rate limiting (20/15min), lockout after 5 fails
  - Access tokens expire in 15 min; silent refresh on the dashboard
  - Role checks server-side; every action written to AuditLog
  - Before production: change JWT_ACCESS_SECRET, JWT_REFRESH_SECRET,
    AGENT_REGISTRATION_TOKEN, CORS_ORIGIN in server/.env (never commit .env)

--------------------------------------------------------------------------------
10. TROUBLESHOOTING (top fixes)
--------------------------------------------------------------------------------
  - Machines offline  → agent heartbeat lost; check SERVER_URL in agent/.env
  - "Loading..." forever → backend not running; check port 5000
  - Attendance empty  → machine not assigned to a lab (no labId)
  - Invalid token     → log out and back in (token expired)
  - Ports in use      → kill $(lsof -ti:5000) and :5173
  - MongoDB error     → whitelist your IP in Atlas Network Access
